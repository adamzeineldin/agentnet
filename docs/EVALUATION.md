# Evaluation

Raw numbers live in [EVALUATION_RESULTS.md](EVALUATION_RESULTS.md), generated by
`make benchmark` from a stored benchmark run (never edited by hand). The same run is browsable at
**Evaluation** in the Control Center. This page states the protocol and what the numbers do and do not show.

## Question

When a target robot (UR5e) faces a *new* scene, does reusing a source robot's (Panda) verified
experience reduce search effort or raise success compared with planning from scratch, and is anything
smarter than replaying the source strategy needed?

## Protocol (fixed before running)

- **Scene families:** `wall_reach_v1` (a wall between start and target) and `wall_roof_v1` (a shorter wall
  with a roof slab above it, so going over is blocked and side routes depend on the robot's body).
  `wall_roof_v1` parameters were widened once (gap 0.10–0.16 m → 0.16–0.30 m) after a probe showed
  *no* feasible route for either robot; this was tuned for solvability, not for any method's result.
- **Dev library:** Panda runs the normal discovery pipeline on dev seeds 0–9 of each family. Capsules stay
  in memory; nothing is published; no UR5e result ever enters the library.
- **Held-out:** UR5e on seeds 100–109 of each family (20 scenes). Each scene retrieves the nearest dev
  capsule of the same family by task-geometry distance.
- **Variants** (same start pose, same candidate set, ≤ 3 physics rollouts, candidates evaluated lazily in
  each variant's own order, stop at the first verified rollout):
  - `baseline_no_sharing` — fixed enumeration order (direct, over, near side, far side × clearances).
  - `retarget_only` — only the retrieved strategy, regenerated on the new scene.
  - `agentnet_offline` — candidates ordered by the retrieved capsule (strategy, same class, source-verified
    alternatives, source failures last).
  - `agentnet_meta` — **not run** (no `MODEL_API_KEY`).
- **Success:** first rollout with endpoint error < 1 cm, zero robot contacts, no joint-limit violations, settled.
- **Accounting:** source discovery cost is excluded from target variants; start-pose IK is shared and excluded
  from per-variant wall time.

## Results (benchmark run `run_20261027_004624_6244c9`, MuJoCo 3.17.0)

| | baseline_no_sharing | retarget_only | agentnet_offline |
|---|---|---|---|
| Success, 20 held-out scenes | 17/20 | 10/20 | 17/20 |
| Median kinematic evaluations, wall_reach_v1 | 2 | 1 | 1 |
| Median kinematic evaluations, wall_roof_v1 | 7 | 1 | **10** |
| Median physics rollouts to first success | 1 | 1 | 1 |

Paired per scene vs no sharing (17 scenes both solved): AgentNet needed fewer kinematic evaluations on 11,
more on 6, never the same; it solved no scene the baseline missed and missed none the baseline solved.
Retargeting failed on 7 scenes the baseline solved. The 3 scenes nobody solved are roof scenes where the
UR5e has no feasible candidate in this template set.

## Interpretation

1. **No success benefit.** Sharing experience did not solve anything a from-scratch search over the same
   candidates could not. With kinematic screening before physics, every method succeeds on its first rollout,
   so the physics budget never binds.
2. **Sharing reduces search effort when the retrieved strategy suits the target's body.** On `wall_reach_v1`
   the Panda's `over` strategy also works for the UR5e (median 1 evaluation vs 2). On `wall_roof_v1` scene 102
   the retrieved capsule was `near_side@0.12` and AgentNet needed 1 evaluation vs 7.
3. **Negative transfer is real.** Most roof-family dev capsules are Panda `far_side` skills; the UR5e's forearm
   collides on far-side routes, and the prior also demotes `near_side` (a Panda failure) — the one route the
   UR5e needs. AgentNet then evaluates all 10 candidates (median 10 vs 7).
4. **Plain retargeting is not enough.** Replaying the source strategy on another body fails half the time.
   Ordering + verification on the target is what keeps success at the baseline level.

## Limits of this evaluation

- 20 held-out scenes, two hand-designed scene families, one robot pair, one direction (Panda → UR5e).
- Ten template candidates; search effort is small in absolute terms (milliseconds), so the difference is
  about ordering, not a compute bottleneck.
- No confidence intervals; with n=10 per family the medians are indicative only.
- The prior uses only the single nearest capsule; aggregating outcomes across the library, or across robots
  with similar bodies, is the obvious next step and is not evaluated here.
- Meta Muse Spark was not evaluated (no API key).
