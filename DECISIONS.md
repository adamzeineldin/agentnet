# Decisions & assumptions

| # | Decision | Why |
|---|----------|-----|
| D1 | Python 3.13 venv (system default is 3.14) | Safer wheel availability for MuJoCo/SciPy; project supports ≥3.11. |
| D2 | Menagerie via sparse git checkout pinned to `f3b6013`, gitignored | Reproducible, only ~81 MB, avoids redistributing model assets. |
| D3 | Panda TCP site added by Nimbotics on `hand` at +0.1034 m z | Menagerie Panda has no EE site; offset is Franka's documented flange-to-TCP. Tagged `declared` in the passport. UR5e uses the model's `attachment_site`. |
| D4 | Use `panda.xml` (with hand) not `panda_nohand.xml` | Hand is real collision geometry and looks like the robot; gripper held open, unused (tool_type says so). |
| D5 | Arm joints = hinge/slide joints on the chain EE→world; actuators must be joint-transmission position servos (bias = [0, −kp, −kv]) | Detects structure from the model; `ctrl` is a joint position target only after this check. |
| D6 | Gravity/Coriolis feed-forward: servo setpoint = q_target + qfrc_bias/kp | Plain PD servos sagged 6–9 mm under gravity (measured). Feed-forward uses MuJoCo's own bias forces from the simulated state; recorded in passport assumptions. |
| D7 | Adaptive settle after the last setpoint (|Δq| < 0.5 mrad, |q̇| < 0.01, cap 2.5 s) | UR5e wrist servos (kp 500) needed ~1–1.5 s; fixed 0.6 s left 4–5 mm error. Settle time is recorded per run. |
| D8 | Position-only IK (DLS, λ=0.05, null-space pull to home, ≤0.15 rad/iter, multi-seed, collision rejection) | Sufficient for a reaching task; orientation constraints can be added if transfer needs approach direction. |
| D9 | Joint-space linear interpolation at ≤1.0 rad/s per joint | Simple, speed-limited; task-space paths come in M2 via IK waypoints. |
| D10 | Collision = any MuJoCo contact involving a robot geom (self/obstacle/floor/env) | Conservative; finger/self contacts at home were checked to be zero for both robots. |
| D11 | Single `ThreadPoolExecutor(max_workers=1)` simulation worker; SSE by polling SQLite | MuJoCo/GL state never crosses threads; no extra infra. |
| D12 | Runs stored as validated Pydantic JSON in SQLite; updates create new records (`model_copy`) | Immutable records, easy replay, schema-versioned. |
| D13 | Frontend data pages are client components under thin server pages | Next 16 `cacheComponents` prerenders shells; live backend data is fetched client-side. `useSearchParams` wrapped in `<Suspense>`. |
| D14 | CORS: regex for localhost/127.0.0.1 any port | Next dev may move off :3000; app is local-only. Override via `NIMBOTICS_CORS_ORIGIN_REGEX`. |
| D15 | Data-mark color `#0ea5c6` | Passed the dataviz validator lightness band and contrast on the dark surface; brighter cyan kept for UI chrome only. |
| D16 | Skill Library / Transfer Lab nav items shown disabled | Avoid UI that does not map to backend data before M2/M3. |
| D17 | Task frame: origin on the floor in front of the robot, +x radial, +y lateral, +z up; placement = translation (+ yaw, not yet supported for boxes) | Capsules carry geometry in a robot-independent frame; target robots re-place it in their own base frame. |
| D18 | Source skill = enumerated route classes × clearances, not RRT | Plan's recommended start; gives interpretable, transferable strategy classes and honest per-candidate failure reasons. |
| D19 | IK tracking along 2 cm task-space steps, each seeded by the previous solution; reject joint jumps > 0.25 rad | Prevents IK branch flips producing sweeping motions between screened samples. |
| D20 | Minimum link-obstacle clearance 10 mm (from `mj_geomDistance` on every 25th physics-rate sample) | Contact-free but grazing paths are rejected as unsafe; threshold recorded in reasons. |
| D21 | Cost = joint path length (rad) + 1.0 × EE path length (m); top 3 feasible by cost get physics rollouts | Matched simulation budget per run; mixed units are documented, weights are not tuned. |
| D22 | Discovery drafts the capsule; publishing is a separate explicit call | Matches the "Publish Experience" step; failed runs can never become validated capsules. |
| D23 | Capability `obstacle_aware_reach` derived at read time from published skills (passport copy) | Stored passport stays a pure model/measurement artifact. |
| D24 | Shared `candidate_search.py` for discovery and transfer; they differ only in candidate order, selection rule and capsule lineage | Same physics budget and checks for both, which the M6 baselines need. |
| D25 | Transfer selection = first candidate verified in prior order (discovery = lowest cost among verified) | Transfer should trust experience and stop early; "rollouts to first success" becomes the measured benefit. |
| D26 | Same-scene transfer uses the capsule's stored TaskSpec (not regenerated); new-scene transfer regenerates the strategy's waypoints on the new geometry | Shows the registry is the source of truth; makes held-out transfer possible. |
| D27 | Compatibility checks are advisory except capsule validation; feasibility is decided by the target's own simulation | Passport reach is a sampled estimate; MuJoCo is the authority. |
| D28 | Both robots use the same placement (0.50 m in front of base) | Both reaches measured ≈0.95 m; strategy reach check reported (61–79% of UR5e sampled reach). |
| D29 | Transfer run's `skill_id` = adaptation capsule id on success; the input skill is `results.source_skill_id` | One field means "capsule this run produced" for both discover and transfer runs. |
| D30 | Meta via raw `httpx` against the OpenAI-compatible Chat Completions endpoint (no SDK dependency) | Injectable `MockTransport` for tests; exact request shape visible and asserted. |
| D31 | Model gets read-only tools only; physics is run by the backend in the validated ranked order | Keeps numerical IK/physics deterministic and makes the simulation budget identical across providers. |
| D32 | Final answer via `submit_ranking` tool (tool_choice only supports "auto"); last round drops tools and forces `json_schema` | Bounded loop that always terminates with a schema-constrained answer. |
| D33 | Caps: 4 tool rounds, 1 revision, 1200 max_tokens per call; cost estimated at $1.25/$4.25 per 1M tokens | Plan's "cap tool rounds and cost"; standard-mode pricing from dev.meta.ai. Contributor mode (cheaper, trains Meta models) not used by default. |
| D34 | "Offline would select" uses physics if that candidate was simulated, else kinematic feasibility (basis recorded) | Avoids extra simulation while never claiming an unmeasured comparison as physics. |
| D35 | Imagination budget = 3 futures; transfer executes the first verified future in provider order | Multiple futures shown; same budget as discovery and baselines. |
| D36 | Presentation replay picks the latest succeeded transfer whose source capsule exists, preferring one with a published adaptation | Replays only real recorded chains; never fabricates or mixes unrelated runs. |
| D37 | Presentation clips at 0.5× with an on-screen label | ~2 s real-time executions are too fast to follow on video; slowing is disclosed. |
| D38 | Visual theme applied to Menagerie skybox/floor textures via MjSpec | Matches the dark UI; textures don't affect dynamics; model hash is over source files and unchanged. |
| D39 | Live presentation uses seed 7 and the offline planner | Seed 7 shows a genuine strategy adaptation (Panda far-side → UR5e over); Meta needs an explicit key + approval. |
| D40 | Held-out protocol: Panda dev library (seeds 0–9) → UR5e eval (seeds 100–109), nearest same-family capsule | Tests reuse on *new* scenes; no target result can leak into the library. |
| D41 | Variants evaluate candidates lazily and stop at first verified rollout; budget 3 rollouts | Makes search effort (kinematic evaluations) a real, comparable cost; all variants share start pose and candidates. |
| D42 | `wall_roof_v1` roof gap widened 0.10–0.16 → 0.16–0.30 m after a probe found zero feasible scenes | A family nobody can solve can't discriminate; tuned for solvability before running any comparison. |
| D43 | Report generated only from the stored run; findings on the UI generated from numbers | Prevents hand-written claims drifting from data; losses are stated automatically. |
| D44 | Playwright runs an isolated stack (temp DB, separate `distDir`) | Running `next build` beside `next dev` corrupted the dev server earlier; tests must not touch dev data. |
| D45 | Separate demo registry (`backend/app/data/demo/`) seeded only by real runs; `seed_demo.py` refuses non-demo paths | Clean screen for recording without deleting dev history; nothing fabricated. |
| D46 | Recording uses a production build in `.next-demo` (`make demo`) | No Next.js dev indicator on video; doesn't disturb `next dev`. |
| D47 | Clips encoded with imageio `macro_block_size=4` | 540 px is even but not a multiple of 8; the default resized frames to 544 px (slight stretch). |
| D48 | Fresh-clone check runs on a copy of `git ls-files -co --exclude-standard` | Tests exactly what a commit would contain (catches missing/ignored files) without committing. |

| D49 | Adopt the handoff's light-default palette, IBM Plex fonts, square surfaces and persistent explicit theme choice | Supersedes the former dark-only cyan UI/data palette (D15). Existing semantic color tokens keep diagrams and evidence readable in both themes. |
| D50 | ParticleArm is a decorative Canvas illustration, not a model preview or simulation result | Port the supplied geometry and motion without presenting its animation constants as measured robot data. Respect reduced motion and clean up frames, observers and event listeners. |
| D51 | Use only available backend measurements in redesigned slots | Show passport DOF/reach/limits, recorded run timings/errors/contacts and benchmark summaries. Omit GPU-hours, storage, environment counts, training curves and predicted success/fit metrics because the API does not supply them. Editable seed inputs remain run parameters, not reported results. |
| D52 | Joint correspondence compares model chain order and allowed range, not an inferred one-to-one mapping | The API supplies joint topology and limits but no correspondence/fit score. Bars are explicitly labelled as relative range spans; transfers continue to carry task geometry and independently solve target IK. |
| D53 | Build memory graph edges only from published capsules and parent-child adaptations | Solid edges identify the publishing robot; dashed edges identify adoption of the parent skill by the adaptation's source robot. No speculative adoption or training state is inferred. |
| D54 | Keep existing routes, labels and backend workflows; link selected original skills into Transfer Lab | Preserve discover/publish/transfer/publish behavior and evidence access. Present remains chrome-less, with shared fonts/colors and a readable video overlay. |
| D55 | Verify each design step on isolated backend/browser stacks and capture production screenshots from recorded test runs | Avoid touching the user's running stack or manufacturing display data. New regressions cover theme persistence, filters, search/graph keyboard interaction and narrow layouts. |
| D56 | Local runs use `muse-spark-1.3-contributor`; cost is priced per model id (unknown model → no estimate) | ~12–20× cheaper ($0.10/$0.20 vs $1.25/$4.25 per 1M tokens) to preserve credits. Requests contain only simulated robot/task data, so contributor-mode training use is acceptable. Default stays standard; set via `META_MODEL_ID`. Amends D33. |
| D57 | Meta calls use `reasoning_effort="low"`, ≤2 tool rounds, a JSON-only final user message with `strict` schema, and tolerant `{...}` extraction; billed calls are kept on `MetaReasoningError` and counted in the run trace | Live runs at default effort spent all 1200 tokens reasoning (empty/prose answer) and 4 rounds went to inspection. Low effort is cheaper and answered correctly. Fallback runs must still show what was spent; `model_used` stays null because the model's answer was not used. Amends D32/D33. |
| D58 | Skill librarian writes a separate, stored `LibraryReport`; it never edits, merges or deletes capsules and never executes its suggestions. Offline rules first; duplicate = same robot + identical task geometry + same strategy, earliest kept | Capsules are immutable evidence and lineage points at specific ids. A report is reproducible from the registry and states each rule's basis, so a model-based librarian can later be compared against it. |
| D59 | Muse librarian may only add model-written text (summary, collection notes, priority rationale) and reorder rule-computed suggestions; text implying hardware/physical/real-world results is dropped server-side; one tool round | Keeps every count and grouping reproducible from the registry while still using the model for judgement and wording. The single live check described simulation results as "hardware", so the prompt alone is not trusted. One round + low effort kept the live report to 1 call ($0.00043). |
| D60 | Playwright e2e backend runs with `MODEL_API_KEY` blanked; Librarian UI defaults to offline rules and labels Muse with its approximate cost | UI tests must be deterministic and free regardless of the developer's `.env`; the transfer test relied on the keyless header label. Users opt in to model spend explicitly per report. |
| D61 | Controller execution goes through URSim (UR's own controller software, PolyScope 5.26, UR5e) via a `ur_rtde` bridge container; results are labelled "URSim controller, not physical" | The only free way to run Nimbotics' output on a real robot controller stack. `ur_rtde` has no macOS wheels, so it runs in a Linux container behind a small HTTP bridge. The same bridge can target a physical e-Series arm by changing `UR_HOST`; untested. |
| D62 | The controller step runs only after MuJoCo verification succeeds, streams the same retimed path (1 rad/s, 125 Hz servoJ paced by our clock, final pose held), and is stored as `results.controller_execution`. It never changes run status or the capsule | Simulation verification stays the gate for publishing. A failed or unreachable controller is still recorded, as failed. The first live attempt failed because `waitPeriod()` paces at the interface rate (500 Hz) and `servoStop()` cut the lagging arm short; that run is kept as recorded. |
| D63 | UR controller base frame = Menagerie base body rotated 180° about z (declared in `robot_catalog.py`); joint zeros and order match | Measured against URSim 5.26.3 on 2026-10-29 at 4 joint configurations: positions agree within 1.1 mm after the rotation. Kept as a regression test. |
| D64 | Real robot data = DROID (`lerobot/droid_100`, MIT, pinned revision), imported as end-effector positions only (JSON in the repo); 8 episodes chosen by a documented rule (task text, 5–20 s, >= 5 cm above the base, <= 0.78 m from the shoulder, moves >= 0.4 m) | DROID records a physical Panda, the same model as Robot A, and its state is Cartesian, which matches Nimbotics' rule of transferring task geometry, not joints. The simulated robots stand on the floor, so paths below the base plane cannot be reproduced; those episodes are excluded rather than altered. The app needs no pyarrow or download at runtime. |
| D65 | A real replay re-solves the recorded path with the chosen robot's IK (robot stands where the recording robot stood), executes it in MuJoCo paced to the recorded duration, and passes only if the simulated end effector stays within 10 mm of every recorded point | The first attempt replayed at the normal 1 rad/s and cut corners (30–70 mm); pacing to the real timing is the fair comparison. With it the Panda reproduces all 8 episodes (3–7 mm); the UR5e passes 2 of 8 (others 10–14 mm), which is reported as failed, not loosened. |
| D66 | Cloud = one Hugging Face Docker Space built from UR's URSim image: API + MuJoCo + static site on :7860, ur_rtde bridge and URSim inside; the pendant's Local→Remote switch is clicked by xdotool at start-up | Free hardware with enough RAM (16 GB) for URSim; Spaces expose one port and run as uid 1000 (URSim verified to run as non-root). Remote mode cannot be set from the dashboard and resets every boot, so it is automated and its readiness is shown live on How it works. |
| D67 | Public copy runs without `MODEL_API_KEY` and caps queued simulation jobs at 3 (HTTP 429 beyond) | Visitors must not be able to spend the Meta credits or pile up work on a 2-vCPU machine. |
| D68 | Free host = a GitHub Codespace (4-core, 16 GB, amd64) that builds and runs the unchanged cloud image via docker-in-docker; Hugging Face stays the paid option | Hugging Face now requires PRO for Docker Spaces (HTTP 402 on 2026-10-31). Codespaces' free tier gives about 30 h a month on an amd64 machine large enough for URSim and a public forwarded port. The same image keeps the switch to Hugging Face a one-command change. |
| D69 | Product renamed AgentNet → Nimbotics everywhere: UI copy, `NIMBOTICS_*` env vars, cookies, MuJoCo site names (`nimbotics_tcp`), evaluation variant `nimbotics_offline`, default DB `nimbotics.db` | One name across the site, API and deploy. Old `AGENTNET_*` env vars are no longer read; local registries were migrated in place (identifier strings only, numbers untouched). The GitHub repo and the live codespace keep their old names. |
| D70 | More arms come from a curated Menagerie catalog (UR10e, KUKA iiwa 14, xArm 7, Lite 6, FR3); the fleet starts as Panda + UR5e and any catalog arm can be added at runtime, which computes its passport first. No user-uploaded models | Every catalog arm was checked with real runs before inclusion (2026-10-31, seeds 42/7, transfer from a Panda skill): UR10e, iiwa 14, xArm 7 and FR3 passed all discover and transfer runs (≤ 1.2 mm); Lite 6 (0.51 m reach) failed 3 of 4 and is kept as an honest small-arm case. Kinova Gen3 (workspace sampler found no collision-free pose) and Sawyer (body collides with the task) were dropped. Uploading arbitrary MJCF would run untrusted files and rarely meets the position-servo contract. |
| D71 | Task placement distance is a declared per-arm catalog fact (`task_distance_m`, default 0.50 m; UR10e 0.60, xArm 7 0.40, Lite 6 0.30) | Placement cannot be read from a model; it is chosen so the task lies inside each arm's envelope, and the passport reports the measured reach next to it. |
| D72 | Sign-in = hand-written OAuth 2.0 code flow for Google and GitHub (httpx), HMAC-signed expiring cookies (stdlib), state cookie checked on callback, relative-path-only `next`. Browsing is open; starting runs, publishing, organizing the library and adding robots need a user only when a provider is configured. Runs record `started_by` (display name). No provider tokens or emails are exposed | Protects the shared free simulator without a new dependency or database server, keeps local dev and tests account-free, and attributes runs. Personal workspaces were not built: they would split the shared memory the project demonstrates. |
| D73 | Console pages use soft surfaces (rounded panels, pills, shadows) and entrance/disclosure motion scoped to `main[data-soft]`; the landing page keeps its square look. Detail most visitors skip (passports, raw rows, event logs, pre-checks, options) sits behind `<Disclosure>`; a page map on Robots/Transfer Lab/Skills/Real Data says how the pages differ; a new Under the hood page walks through one stored transfer | User feedback: too much data at once, unclear page differences, "blocky" UI, and the librarian/mapping were opaque. Every number on Under the hood is read from the stored run and skill; when the learner used a new layout, the two paths are not overlaid. Supersedes the "square surfaces" part of D49 for console pages. |
| D74 | Run progress survives proxies: the SSE stream sends a `: keep-alive` comment every 15 s, and the browser falls back to polling the run record (replaying missed events) if the stream drops | On the Codespaces link the stream was cut after exactly 100 s without bytes (measured 2026-10-31); long queued replays then looked like a dead backend. The run always continued on the server. |
| D75 | Video size and frame rate are configurable (`NIMBOTICS_RENDER_WIDTH/HEIGHT`, `NIMBOTICS_VIDEO_FPS`); the cloud image uses 640×360 at 15 fps; frame spacing is derived from the fps | Software (OSMesa) rendering dominated cloud replays (139 s for a 16 s replay at 960×540, 30 fps). Only the clip changes; physics, checks and stored numbers do not. Local runs keep 960×540 at 30 fps. |
| D76 | Information architecture: six nav items (Home, Try it, Robots, Skills, Real data, Results); How it works lives on the home page below the hero (old route redirects); Under the hood is folded into Try it as "What just happened" for the user's own run; Skills are grouped by task (one card per layout, one row per robot, with "learned it itself" / "learned from X" and links to teach the rest); Results lead with a verdict computed from the stored benchmark, with a caveat whenever sharing did worse on any kind of layout | User feedback: hard to navigate, transfer unclear, skills "super unintuitive" as a list of per-run capsules, Results too dense. Capsules are unchanged in storage (immutable evidence); only their presentation is grouped. Supersedes the page map and the separate Under the hood page from D73. |
| D77 | Runs are watched live: the worker publishes the newest rendered frame per run (JPEG, ≤ 10 per second, dropped when the run ends) and the page polls `GET /api/runs/{id}/live`; progress events carry each route's geometry, every kinematic check and every physics try, so the page draws the routes and stages as they happen. The same view stays after the run as its record | User feedback: a run was a spinner and then a new screen, with no sense of what happened or how the skill was mapped. Frames come from the renders that make the clips, so nothing extra is simulated and nothing is invented. Polling (not SSE) keeps one request per frame and works through the Codespaces proxy. |
| D78 | Every physics try is recorded as its own clip (448×252) with its MuJoCo hand path, for discovery and transfer alike; headless evaluation skips the clips. The cloud image renders without shadows and reflections (`NIMBOTICS_RENDER_EFFECTS=0`) | Before, only the chosen route had a video, so failed tries could not be seen. Shadows were ~80 % of an OSMesa frame on the codespace (240 → 48 ms at 640×360, measured 2026-11-01); without them the extra clips cost less than the old single clip: a full discovery run on the codespace took 16.6–17.6 s with one clip and 9.4 s with three (measured 2026-11-03). Physics and checks are unchanged. |
| D79 | Run list: compact records by default on the All runs page (`full=false`: no event log, small result keys), server-side status filter and paging; a run opens in a dialog over the list. The cloud container keeps its registry and clips on a named Docker volume | The old page fetched ~45 KB per run every 5 s, missed benchmark runs in its filters, and opened details above the list, off screen ("can't see all of them"). Redeploys wiped every run recorded on the live site. |
| D80 | Own domain (nimbotics.net) through a Cloudflare Tunnel started by `deploy/codespace.sh` when `CLOUDFLARE_TUNNEL_TOKEN` is set; `NIMBOTICS_PUBLIC_URL` names the domain, and `www.` redirects to it with 308 (`app/canonical_host.py`) | A Codespaces link cannot take a custom domain (GitHub's proxy only answers its own hostname). The tunnel is outbound only, free, gives HTTPS, and works unchanged on any later host (VPS). One canonical host keeps sign-in cookies and OAuth callbacks on one address. The site is still down whenever the codespace is stopped. |

## Open questions / blockers
- Meta Model API: live since 2026-10-29 on `muse-spark-1.3-contributor` (see PROGRESS M7). Keep spend minimal.
- Deadline verified: Nov 4, 2026, 9:00 PM ET. Official Rules (video length, required fields, repo/license, asset
  rules) were not publicly reachable — check the participant portal (see docs/SUBMISSION.md).
- The repo lives under `~/Documents`; macOS created `* 2.*` conflict copies inside `frontend/.next` (likely a sync
  service racing with Next's writes). Consider moving the repo outside synced folders.
